# Журнал изменений

## 0.1.14 - 2026-11-22

- Проекты заработали: в Chat можно создавать проекты (сообщение «Проекты пока недоступны» больше не появляется), задавать инструкции проекта и добавлять в его базу знаний текст, документы Word / Excel / PowerPoint, PDF и картинки. В диалогах, начатых внутри проекта, запрос модели включает инструкции проекта и всю его базу знаний. Проекты, их базы знаний и диалоги внутри них хранятся на этой машине и не пропадают после перезапуска; проекты можно переименовывать, помечать звездой, архивировать и удалять, а диалоги — переносить в проект и обратно. Поиск по базе знаний не делается: каждый диалог отправляет модели её целиком, так что большая база занимает контекст и обходится дороже (добавлена метка кэширования — с ней часть расходов экономится, если апстрим поддерживает кэш промптов). PDF и картинки уходят модели исходными файлами — нужно, чтобы апстрим поддерживал ввод PDF / изображений. Источники синхронизации вроде Google Drive и GitHub, а также общий доступ для нескольких человек не поддерживаются.
- Маркетплейс расширений: на странице «Расширения» появился маркетплейс, где можно искать, устанавливать и обновлять расширения. «Официально проверенные» лежат в репозитории claude-mom-extensions, их код смотрели перед слиянием; «Расширения сообщества» берутся из репозиториев самих авторов, их никто не проверял, поэтому перед установкой спрашивают подтверждение ещё раз. Только что установленное из маркетплейса расширение включается сразу, при обновлении его переключатель сохраняется; когда у установленного расширения выходит новая версия, приходит уведомление.
- В манифестах расширений `author` и `description`, равные `null`, больше не считаются ошибкой формата.

## 0.1.13 - 2026-11-22

- Расширения страниц: в ClaudeMom появилась страница «Расширения» — на страницу Claude можно добавлять свои скрипты и стили. В комплекте два примера (настольный питомец Рыжик и широкая область диалога), по умолчанию они выключены; можно импортировать .zip или папку с manifest.json. Включение, импорт и удаление действуют после обновления страницы Claude, перезапуск не нужен.
- Интерфейс ClaudeMom перешёл на навигацию слева: Апстрим / Настройки Claude / Расширения; версия и проверка обновлений переехали в низ боковой панели.
- С апстримом OpenCode Go Chat и Cowork больше не выдают «400 MissingSessionID»: запросы к opencode.ai несут идентификатор сессии (`x-opencode-session`), неизменный в пределах диалога, — кэш апстрима теперь срабатывает. (#42)
- В Настройки → Память сохранение воспоминаний и переключатель памяти больше не выдают «Не удалось сохранить воспоминания». В локальном режиме синтеза памяти нет, запросы к модели воспоминаний не содержат; изменения здесь живут только до конца текущего запуска. (#43)
- Открытие страницы проектов больше не роняет всю страницу из-за формата списка сессий. (#40)

## 0.1.12 - 2026-11-20

- Если задан только системный прокси (без TUN-режима), запросы модели к публичным апстримам теперь тоже идут через него — вместо прямого подключения, которое апстрим отклонял по региону (`403 region_blocked`) или которое просто не устанавливалось. Апстримы на этой машине и в локальной сети по-прежнему подключаются напрямую. (#36)

## 0.1.11 - 2026-11-20

- Коннекторы заработали: коннекторы на странице плагинов (удалённые MCP-серверы; проверены Product Hunt и Notion, остальные коннекторы, разрешающие самостоятельную регистрацию клиента, подключаются так же) можно открыть и подключить кнопкой «Добавить» — после этого в новых сессиях Cowork и Code доступны их инструменты; их также можно отключить и удалить. Коннекторы, где нужен вход, открывают страницу авторизации провайдера в системном браузере, а после входа автоматически возвращают вас в Claude; токены хранятся на этой машине. В коннекторы, которые признают только клиентов, зарегистрированных самим Anthropic (Slack, Gmail, Google Drive, Asana и т.п.), войти не получится — сразу сообщается, что подключение не удалось. Вкладка Chat пока не использует инструменты коннекторов.
- Поиск на странице плагинов починен: в 0.1.10 что ни ищи — выводились только установленные плагины.
- Раздел «Коннекторы» на странице плагина больше не висит на «загрузке»; переход к коннектору из списка больше не выдаёт «Не удалось загрузить эту страницу».

## 0.1.10 - 2026-11-20

- Плагины теперь можно устанавливать: плагины на странице плагинов, у которых есть репозиторий с исходниками (Skills / хуки / команды вроде Superpowers и frontend-design), можно открыть, посмотреть детали и файлы и установить кнопкой «Добавить»; после установки они доступны в новых сессиях Cowork и Code, их можно и удалить. Детали плагина берутся из публичного каталога Anthropic, а пакетом служит исходный код проверенного коммита в GitHub-репозитории плагина, так что для установки нужен доступ к GitHub. Пункты-коннекторы (те, что вызывают серверы Anthropic от вашего имени) по-прежнему не открываются и не устанавливаются. (#25)
- macOS: в «Записанной» версии Cowork больше не выдаёт «401 Invalid bearer token». Запросы из виртуальной машины теперь идут через локальный сервис, а не напрямую к официальным серверам через системный прокси. Виртуальная машина принимает только сертификаты, доверенные по базовой политике: при включённом Cowork тем, кто раньше доверял локальному сертификату, нужно ещё раз нажать «Доверять сертификату».
- Починена ошибка «Cowork сейчас недоступен» при отправке задачи Cowork: добавлен `/api/bootstrap/<org>/system_prompts`, и `system_prompts` записывается в bootstrap. Промпты во время работы читаются из локального `app.asar` (официальный текст в репозитории не распространяется); если прочитать не удалось, используется встроенный запасной вариант.
- Починено падение всей страницы плагинов с «Не удалось загрузить плагины. Проверьте подключение к интернету и повторите попытку» (появилось в 0.1.9): каталог плагинов снова отображается, а если Anthropic недоступен — показывается пустым. (#25)
- Если Chat-диалог открыть заново после перезапуска локального сервиса, в нём остаётся модель, выбранная в прошлый раз, а не сбрасывается на модель по умолчанию.

## 0.1.9 - 2026-11-18

- Починено: в интерфейсе версии 11-17 уже имеющиеся ответы показывались как «Не удалось загрузить это содержимое». Если у старых или новых сессий нет списков вроде вложений, теперь возвращается пустой список; существующие вложения не очищаются. Также дополнен список типов фреймов, который читает страница. (#26, спасибо #29 за разбор)
- Починлены недостающие обязательные поля в каталоге плагинов, реестре, списке расширений и в проверке установленных плагинов; если локальных плагинов нет, показывается пустой список. Локальный mock «Записанной» версии не содержит деталей и пакетов официальных плагинов, поэтому просмотр и установку официальных плагинов в этот релиз не добавляли. (#25, #30)
- Список моделей теперь подтягивается и у апстримов, чей адрес заканчивается на `/anthropic` (например, DeepSeek): если прежний адрес списка моделей возвращает 404 или 405, пробуется список моделей по корневому пути; ошибка авторизации или таймаут сразу показываются как ошибка. (#20)

## 0.1.8 - 2026-11-17

- Починено: в интерфейсе версии 11-17 все модели апстрима в селекторе показывались с кнопкой «Обновить», и любая попытка переключиться вызывала ошибку (переключаться обратно на 11-07 больше не нужно).
- Windows: запросы из виртуальной машины Cowork теперь идут через локальный сервис и не подключаются напрямую к официальным серверам с «401 Invalid bearer token».
- Windows: в Настройки → Дополнительно → Cowork добавлена кнопка «Установить системный сертификат» (нужно разрешение администратора). Виртуальная машина Cowork доверяет только системным сертификатам, без него возникает ошибка сертификата x509; при отзыве доверия системный сертификат тоже удаляется.

## 0.1.7 - 2026-11-17

- Починено: в поле ввода на главной странице пропал переключатель «Чаты | Cowork», и вход в Cowork было не найти.
- Данные интерфейса обновлены до версии claude.ai от 2026-11-17; в Настройки → Версия можно вернуть предыдущую версию 11-07.
- В Настройки → Интерфейс добавлен пункт «Встроенная»: используется собственный новый интерфейс Claude (сторонний режим), он обновляется вместе с Claude и не требует доверия к локальному сертификату; китайский интерфейс и голосовой ввод пока не поддерживаются, функций, привязанных к аккаунту (управление компьютером и т.п.), нет. По умолчанию остаётся «Записанная».
- В настройках появился пункт «Объединённая главная страница (эксперимент)»: главная страница, которую Claude тестирует на небольшой доле пользователей, — чаты и Cowork в одном поле ввода; по умолчанию выключена.
- Убран пункт «Использовать встроенный интерфейс машины (экспериментально)», его заменила «Встроенная».

## 0.1.6 - 2026-11-16

- Заголовки диалогов в Chat и Cowork теперь генерирует модель апстрима — вместо безликого «New task» или пустоты; диалоги можно переименовывать и удалять.
- Починено: часть запросов Chat теряла текст вопроса после сжатия.
- Windows: починена диктовка, которая не подключалась (голосовой сервис отдавал 503).
- Починена ошибка «Invalid BFF response format» при отправке задачи в Cowork.
- Починена ошибка Artifacts «policy check couldn't get through».
- Локальный сервис теперь предпочитает системный Node.js (22+), а не тот, что тащится с ChatGPT / Codex; откат к ним — только если системная версия слишком старая.

## 0.1.5 - 2026-11-16

- Починено «не удалось скачать Claude Code (IDLE_TIMEOUT)» при первом запуске Code / Cowork: большие файлы теперь конвертируются по ходу загрузки, а не читаются целиком в память (при скачивании память больше не раздувается до нескольких гигабайтов).
- Починено «связь с ответом Claude прервалась» сразу после отправки в Chat: если апстрим ошибается (неверный Key, несуществующая модель, нестандартный ответ шлюза и т.п.), его причина теперь показывается прямо в ответе; шлюзы с CRLF-разделителями, без конечных событий и без стриминга тоже поддержаны.
- Windows: починено сообщение «управление компьютером не включено для вашего аккаунта» при включении Computer Use в настройках.
- Windows / macOS: если другой пользователь той же машины держит Claude открытым, он больше не считается вашим и не висит с вечным «запущено».
- Починены пустые сообщения при открытии существующего диалога.
- Встроенные примеры навыков (в локальном режиме не скачиваются) больше не показываются включёнными, и Claude перестал при каждой синхронизации пытаться их скачать и репортить провал.

## 0.1.4 - 2026-11-16

- Починено открытие тысяч соединений локальным сервисом при первом запуске Claude (в прокси и файрволах видно кучу node-соединений): запросы к апстриму теперь делят соединения и ограничивают конкурентность.
- Починено: при свежей установке интерфейс мог получить другую раскладку, а вкладка Code — вечно грузиться; первый запуск больше не требует прямого доступа к claude.ai — меньше «Couldn't connect to Claude / Bad Gateway».
- Когда Claude закрывает соединение, локальный сервис закрывает и своё — соединения больше не копятся; соединения к прочим доменам (статистика, отчёты об ошибках) тоже идут через системный прокси.
- В Настройки → Дополнительно добавлен пункт «Использовать встроенный интерфейс машины (экспериментально)» — выключен по умолчанию, пока только для тестов.

## 0.1.3 - 2026-11-15

- Windows: починено — в новых сборках десктопа Claude на главной странице не было переключателя «Чаты | Cowork»; теперь Cowork открыт по умолчанию. Не нужен — отключите в Настройки → Дополнительно → Cowork.
- В некоторых версиях Claude нет `ion-dist.asar` — интерфейс распакован в каталог; из-за этого локальный сервис не запускался и бесконечно показывал «локальный сервис не запущен». Теперь поддерживаются оба варианта.

## 0.1.2 - 2026-11-13

- Импорт из cc-switch: читаются и провайдеры, настроенные отдельно для десктопа Claude (страница «Claude Desktop» в новых версиях cc-switch); одинаковые пары адрес + Key импортируются только один раз.
- Импорт из cc-switch: база данных ищется по правилам самого cc-switch — находится даже при переопределённом в его настройках каталоге конфигурации.
- Если в cc-switch есть только провайдеры формата OpenAI, теперь объясняется причина, а не сухое «не найдено».

## 0.1.1 - 2026-11-12

- macOS: Claude запускается через систему (LaunchServices), поэтому права доступа — запись экрана, универсальный доступ и другие — считаются самим Claude и больше не показываются как «не запрошены».
- В Настройки → Дополнительно добавлен переключатель «Включать фоновый режим на новых системах» (выключен по умолчанию): если Claude на свежем macOS пишет «фоновый режим пока не поддерживается», он снимает ограничение по версии системы. Claude это не валидировал — возможна нестабильность.

## 0.1.0 - 2026-11-12

Первый релиз: самостоятельная программа, выделенная из CodexPlusPlus.

- Полнофункциональный режим оригинального десктопа Claude (Chat / Code / Cowork, китайский интерфейс) с прямым подключением к вашему апстриму (Base URL + Key).
- Несколько апстримов с мгновенным переключением; импорт провайдеров Claude из cc-switch или локальные шлюзы Magpie / Codex++ как апстрим.
- Локальная диктовка (SenseVoice, офлайн-распознавание).
- Автообновление.
